# SHA-256 (Secure Hash Algorithm 256-bit) 🔑

## Overview
SHA-256 is a cryptographic **hash function** from the SHA-2 family (NIST FIPS 180-4). It maps any input — a byte or a gigabyte — to a fixed 256-bit (32-byte) *digest* that acts as a fingerprint of the data. CryptoLens computes the digest and walks through the padding, a live avalanche demonstration, the internal compression, and the security pitfalls.

> **Hashing is one-way.** There is no "decrypt" for a hash: you cannot recover the input from the digest. That irreversibility is the entire point — SHA-256 is for integrity and fingerprinting, not encryption.

## Features
- One-way, deterministic, fixed-size 256-bit digest
- Hex and Base64 output
- Per-input padding walkthrough (the `1` bit, zero fill, 64-bit length)
- **Live avalanche demo**: flips one input bit and counts how many output bits change
- Initial hash constants shown as "nothing-up-my-sleeve" numbers
- Family context (SHA-1 vs SHA-2 vs SHA-3) and real-world uses

## Where SHA-256 Sits
| Family | Status |
|--------|--------|
| SHA-1 (160-bit) | **Broken** — practical collisions since the 2017 SHAttered attack. Do not use. |
| SHA-2 (SHA-224/256/384/512) | Secure and standard. SHA-256 is the most widely deployed. |
| SHA-3 (Keccak) | A structurally different backup family, not a replacement for SHA-2. |

## The Four Cryptographic Properties
1. **Deterministic** — the same input always yields the same digest.
2. **Fixed size** — any input maps to exactly 256 bits.
3. **One-way (pre-image resistance)** — infeasible (~2²⁵⁶ work) to find an input for a given digest.
4. **Collision resistance** — infeasible (~2¹²⁸ work) to find two inputs with the same digest.

Plus the **avalanche effect**: flipping a single input bit flips roughly half of the 256 output bits, so digests reveal nothing about how "close" two inputs are.

## How It Works

### Step 1 — Preprocessing (padding)
The message is padded to a multiple of 512 bits:
1. Append a single `1` bit.
2. Append `0` bits until the length is 448 mod 512.
3. Append the original message length as a 64-bit big-endian integer.

Example for `"abc"` (24 bits): `24 + 1 (the '1' bit) + 423 (zeros) + 64 (length) = 512 bits` = one block. Encoding the length in the padding is what prevents one message from colliding with a padded form of another.

### Steps 2–4 — Schedule, compression, output
- **Message schedule:** each 512-bit block expands into 64 32-bit words `W[0..63]` via rotations, shifts, and XOR (the σ0/σ1 functions).
- **Compression:** eight working variables `a..h` (seeded from the running hash) run through 64 rounds mixing in `W[t]` and round constants `K[t]` (the Ch, Maj, Σ0, Σ1 functions), then feed back into the hash.
- **Output:** after the final block, `H0..H7` are concatenated into the 256-bit digest.

The initial hash values `H0..H7` are the fractional parts of the square roots of the first eight primes — "nothing-up-my-sleeve" numbers that demonstrate the constants hide no backdoor:
```
6a09e667 bb67ae85 3c6ef372 a54ff53a 510e527f 9b05688c 1f83d9ab 5be0cd19
```

## Security Considerations
| Point | Detail |
|-------|--------|
| Strength | Collision ≈ 2¹²⁸, pre-image ≈ 2²⁵⁶ — both far out of reach |
| **Length-extension** | Given `SHA-256(secret‖msg)` and the length, an attacker can compute `SHA-256(secret‖msg‖pad‖extra)` **without the secret**. Never authenticate with `hash(key‖message)` — use **HMAC** (menu 6) |
| **Not for passwords** | SHA-256 is fast, so attackers try billions of guesses/sec. Use a slow, salted KDF — **PBKDF2/Argon2id/Scrypt** (menu 7) |

SHA-256 itself is unbroken; these pitfalls come from using it in the wrong role.

## Real-World Uses
- File/download integrity checksums and Git object/commit IDs
- Digital signatures (the hash is signed, not the whole document)
- Proof-of-work in Bitcoin and other blockchains
- The core primitive inside HMAC-SHA256 and many key-derivation functions

## Troubleshooting
| Symptom | Cause | Fix |
|---------|-------|-----|
| Different digest than expected | Input differs by whitespace/encoding | Ensure identical bytes (UTF-8) |
| Trying to "decrypt" a hash | Misconception — hashing is one-way | Store/compare digests; use encryption (AES) if you need reversibility |
| Slow on huge files | Hashing all bytes | Stream the file in chunks rather than loading it whole |
